# Novel Forge v2.2.0 — One Run to a Packaged Book on a Local Model

Novel Forge already contained everything a one-run completion on a non-frontier model needed. All of it was well built. Almost none of it could be reached from the path a writer, or an automated run, actually took.

- **The small-model execution profile** — per-job token budgets, constrained decoding, Gemma fingerprint qualification — existed and was unreachable. `--model-profile` was parsed by both option parsers and discarded by every caller.
- **The per-scene execution machine** — bounded context, isolated jobs, deterministic validation, five scene critics, targeted repair, ordered acceptance — existed and had no driver. `advanceChapterExecutionStep` advanced exactly one node per call, so a novel required roughly two thousand host-driven tool calls, and the automated `/novel-run` path never used the machine at all.
- **Run targets past manuscript review** did not exist, and **headless packaging** existed with exactly one caller: the browser wizard's own handler. On a machine with no browser, a book could be drafted and reviewed and could never be packaged.
- **Sane defaults for the model in the room** did not exist. Every new project defaulted to the widest context budget paired with the least-supervised quality tier — the combination least likely to work on a weak model, in a package whose stated differentiator is constrained runtimes.
- **A way to measure any of this** did not exist. The project's author-velocity baseline evaluated four hand-authored fixtures — a schema test for a counter, not evidence about the workflow.

This release is wiring, done in the order that made each next piece reachable: make the small-model profile selectable and make its prompts fit inside the profile's own budget; bound the repair cycle, because a driver loop over an unbounded cycle is a defect amplifier; add the driver loop; let a run aim at the finished book instead of stopping partway; choose defaults automatically instead of handing out the riskiest combination to everyone; measure what a run actually costs from real traces instead of hand-typed fixtures; and take the first step away from hand-authored YAML entirely, on the highest-value case.

## Added

- **`--model-profile` reaches every path that reads it.** `/novel-start` and `/novel-organize` write `runtime.model_execution_profile` into the new project; `/novel-draft` and `/novel-run` accept it as a per-invocation override snapshotted on the persistent run, so a resumed run keeps the profile it started with. `custom` is rejected at parse time with the selectable list. The resolved profile appears in `/novel-status`, `/novel-budget`, and the session handoff beside genre, runtime, and quality.
- **A 135-cell prompt-compile matrix** (every stage spec × every runtime profile × every genre, with worst-case evidence and revision-ticket load) runs in CI and in `benchmark:prompts`. It caught the defect that motivated it: the `book-plan` prompt exceeded `tiny-local`'s instruction ceiling, so that profile bricked permanently at stage three of eleven, invisible because the existing benchmark only ever compared `full` against `local`.
- **A driver loop for chapter execution.** `runChapterExecution` advances the persisted scene state machine to a real stop — a writer gate, a blocker, a pause, budget exhaustion, the scene repair limit, or an abort — instead of one node per call. `/novel-run` now routes every chapter with an executable contract through guarded scene execution, reports how many chapters used which path, and relays the same disclosure advisory a plain `draft-chapter` event returns when it falls back.
- **A run can be aimed at the end of the book.** `--until packaging` and `--until complete` join the existing gate targets. `/novel-package --apply` produces the complete package — manuscript, EPUB, DOCX, metadata, marketing copy, manifest, report — without a browser, so a headless machine can finish a book at all. The wizard remains the default for interactive work.
- **The human reader checkpoint is visible from drafting onward**, not only at the last gate, and a writer who chooses to publish without one now records that choice explicitly — subject `package-without-reader-evidence` in `series/decision-ledger.yaml` — rather than crossing it with a flag.
- **`/novel-start` recommends a runtime profile from the host model's detected context window**, reporting its evidence, with `--runtime-profile` and `--model-profile` always overriding it. The README documents running the isolated workers against a local model end to end.
- **Author-journey traces recorded from real runs** — guarded events, writer approvals, host turns, context size, and stops — replace hand-authored fixtures as the source of author-velocity measurement, reported through `summarizeJourneyVelocity`.
- **`novel_complete_chapter_contract`** accepts the two decisions that are genuinely the author's — `required_end_state` and `forbidden_changes` — as typed values, derives the two fields that are graph queries, and serialises the YAML itself. A malformed scalar in a hand-authored contract is no longer possible for this event, because there is no longer YAML to hand-author.

## Changed

- The repair cycle inside guarded scene execution is bounded by the runtime profile's `maxRepairAttempts`, which existed but was read by nothing; a scene that cannot pass validation blocks with `repair-limit` instead of cycling.
- No runtime profile caps a persistent run at one chapter; the `--max-chapters` ceiling rises from 10 to 200. Per-chapter isolation is now provided by the driver loop re-reading project state every iteration, not by refusing to continue.
- Affordability thresholds for the capacity advisor come from each runtime profile's own budget rather than hardcoded window sizes.
- The book-plan prompt omits its nine public-review rules whole when a project has no review evidence yet, and splits into two phases feeding one guarded event when the full contract still exceeds a compact instruction budget.

## Compatibility and boundaries

`PersistentQualityDraftResult.chapters` entries are now outcome records (`chapter`, `path`, `reason`) rather than paths, the orchestrator and execution results are named fields (`draft`, `execution`), and the result carries `advisories` that callers must relay. Everything else is additive: `modelExecutionProfile` is optional wherever it appears, runs and projects recorded by earlier versions remain readable, and a project without an explicit model profile resolves to `host-default` exactly as before.

None of this changes what this project will and will not do automatically. The exact-model execution profile is recommended only when a model is actually named — never guessed. An undetectable context window defaults to the conservative `local` profile rather than blocking on a question. The `economy` quality-tier default is unchanged, because raising it would increase spend and this project does not silently increase spend. Packaging without recorded reader evidence still requires an explicit, durable writer decision, still downgrades to a warning rather than disappearing, and the decision itself never becomes reader evidence — the `reader-checkpoint` module is read-only by construction. Journey traces are diagnostic, live only under the already-ignored `.pi-book` tree, and are held to the same privacy rule as all other telemetry: never prompts, prose, source excerpts, model output, reasoning, or credentials. Derived chapter-contract fields still name only records that already exist in the story ledgers; a project with empty ledgers derives nothing rather than inventing a hollow contract, and every ID a typed call supplies is still checked against those ledgers.

No project schema, workflow state, evidence content, human gate, or guarded-transaction rule was removed or narrowed. Nothing in this release lets automation cross a gate or apply a creative change outside one guarded event.
