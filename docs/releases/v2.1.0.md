# Novel Forge v2.1.0 — Relationship Inheritance and Ending-Contract Evidence

Two gaps where the project already held the right information and then made the writer carry it by hand.

`series/canon.yaml` has always modelled relationships as first-class locked records — state, trust level, what is public and what is private, what remains unresolved. Next-book inheritance ignored them. It offered flat canon facts and open story threads, and a couple's standing at the end of book two had to be re-derived from memory when book three was planned. In a series, that is the state most likely to be gotten quietly wrong, and the one readers notice first.

Romantasy declares an `ending_contract` in `genre.yaml` — `hea`, `hfn`, `series-progress`, or `tragic-by-design` — and nothing ever checked that the finished book delivered it. The genre's `endingRules` were prose guidance to the drafter, not a checked condition of packaging. A book could be sold on a promise the manuscript did not keep, and the workflow would have nothing to say about it.

## Added

- **Locked canon relationships are inheritable.** `buildNextBookInheritanceProposal` now surfaces every locked `canon.relationships[]` entry alongside canon facts and open threads, and `createNextBookFromDecision` accepts `inheritedRelationshipIds`, validating each against the locked set exactly as inherited canon IDs are validated. Selected relationships are written to the new book's `inherited-context.yaml` as `inherited_relationship_ids` and listed in the inheritance report under "Continuing relationships". The browser next-book wizard exposes the same selection.

- **A delivered ending must be declared and must match.** `book-strategy.yaml` gains an optional `delivered_ending` field — a disposition plus a note — writable through the existing state-neutral `research-update` event at `manuscript-review` or `packaging` stage. A new blocking `ending-contract` packaging checklist item requires that declaration to exist and to match the contract declared in `genre.yaml`; a mismatch names both values and points at the two legitimate repairs (revise the ending, or change the declared contract through a `plan-change` event).

## Boundaries

The ending-contract check **does not read the manuscript**. Whether a scene reads as a happily-ever-after is human judgment, not a deterministic property, and this project does not pretend otherwise — the same boundary that keeps automated diagnostics out of `reader-experiments.yaml`. What is deterministic is whether the writer has answered the question at all, and whether that answer matches the promise the book was planned on. The check makes sure the question is asked and answered before packaging; it does not grade the answer.

The check applies only to `romantasy` books. Thriller and historical-fiction packaging is unaffected.

## Compatibility

- `inherited_relationship_ids` is optional on `InheritedContext`, so `inherited-context.yaml` files written by earlier versions remain readable and valid.
- `delivered_ending` is optional on `book-strategy.yaml`; existing files parse unchanged. The packaging checklist item is what requires it, and only for romantasy.
- No existing event type, gate, schema field, or validation rule was removed or narrowed.

## Release hygiene note

The 2.1.0 feature work landed in commit `f6f48b3` with the package version bumped and the changelog written, but without the rest of the release set: `NOVEL_FORGE_VERSION` still reported `2.0.1`, these notes did not exist, `README.md` and `RELEASE.md` still pinned 2.0.1, `verify:release` still targeted the 2.0.1 checker, and no `v2.1.0` tag was created. Four tests failed on that drift, so the default branch was red and any project created from it stamped itself `2.0.1`.

`RELEASE.md` already requires package metadata, lock metadata, runtime constants, compatibility tests, changelog, release notes, and install examples to move together, with the annotated tag created last. This release completes that set. The features themselves were unaffected and are unchanged here.

## Upgrade

Install from the pinned `v2.1.0` tag.
