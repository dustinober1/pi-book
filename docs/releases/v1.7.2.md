# Novel Forge v1.7.2 — Guarded YAML Authoring Guidance

v1.7.2 is a guidance-only patch. It changes no project schema, workflow state, or evidence content.

## Fixed

- `SKILL.md` now requires quoting any YAML scalar containing `: ` (a colon followed by a space) before submitting a guarded event. Without this, a colon inside a prose field such as a `description` reads as a nested mapping and the whole file fails to parse.
- `SKILL.md` now requires using only the exact schema field names for nested objects inside guarded event payloads, and points to `src/domain/schemas.ts` (and the matching `v1-3-*`/`historical-fiction` schema module) to check the shape before writing an object of a kind not yet written in the session.
- `references/templates/novel/remarkability.yaml` documents the exact allowed keys for `signature_moments`, `productive_disagreements`, and `recurring_motifs`, so a fresh book plan has a concrete field pattern to copy instead of inventing descriptive extra keys.

This fixes a real failure mode: a `book-plan` submission whose `remarkability.yaml` payload used an unquoted colon in a signature-moment description, and then — on its one permitted retry — added invented extra keys that failed schema validation with a generic "additional properties" rejection. Both mistakes are now called out explicitly before the model writes the file, instead of being discovered only after a rejected transaction.

## Upgrade

Install from the pinned `v1.7.2` tag. This patch changes no project schema, workflow state, or evidence content, so existing projects remain fully compatible.
