# Novel Forge v1.9.0 — Actionable Rejections and Dry-Run Validation

v1.9.0 makes a rejected event tell an author agent exactly what to fix, and adds a way to find that out without spending an event. It changes no project schema, workflow state, or evidence content, and validation strictness is unchanged.

## Added

- **`novel_validate_event`** validates a proposed event and reports the result instead of applying it. It runs the identical contract — required outputs, YAML and schema shape, profile packet fields, cross-artifact references, and domain integrity — but writes nothing, creates no Git checkpoint, advances no stage or gate, and consumes no retry budget. `SKILL.md` and the generated stage prompts now direct agents to converge with it before applying, which moves the whole iteration loop off the transactional path.

## Fixed

- **Schema failures name the field.** A failed union previously reported `Expected union value` at the union's own path — or, worse, collapsed to `/: must be equal to constant` repeated eight times — which said an entry was wrong but never which field. Guarded files use unions heavily (research-ledger items, plot-grid rows, remarkability entries), so this cost entire rejection rounds. Union errors are now expanded against the closest-matching variant, so the report names concrete fields with real instance paths; a union of literals lists its allowed values; and output is deduplicated and capped with an honest remainder count.
- **Packet findings name their chapter.** Profile validators see one packet at a time and could not name the chapter, so a four-packet book plan produced 32 indistinguishable lines. Each packet finding is now attributed to its chapter.
- **Payload-fixable blockers are retryable.** Profile, remarkability, reader-evidence, book-strategy, packet-window, research-and-friction, and missing-required-output blockers previously fell through to the `unknown` rejection code, which instructed the agent to stop and surface a blocker it could have corrected itself. They now classify as `payload-validation`, which is retryable and non-reloading like schema and reference failures.

These come from measuring a real v1.8.0 planning session: 8 `book-plan` submissions over 25 minutes and 551 KB of resubmitted payloads. Three rejections were repeat visits to one file whose errors named no field, and two more were detours caused by a retryable blocker being told to stop.

## Compatibility and boundaries

The same events are accepted and the same events are rejected as before. Only diagnosis changed, plus the new read-only tool. Existing projects remain fully compatible.
