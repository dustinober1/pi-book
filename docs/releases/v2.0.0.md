# Novel Forge v2.0.0 — Making the Quality Path the Default Path

Novel Forge already contained three independent subsystems for catching prose that reads as generated. All three were well built. None of them could be reached from the path an agent actually took.

- **prose-lint** carried sixteen style-tell rules — em-dash density, `not X but Y`, three-part cadence, negative parallelism, aphoristic paragraph closes, filter words, repeated closing syntax. It was referenced from exactly one place in the codebase, inside the act and manuscript review prompts, and it blocked nothing. No chapter-level path ever ran it.
- **repetition memory → style card → context capsule** computed sentence openings, dialogue tags, gestures, metaphors, chapter openings and scene endings deterministically from the manuscript. It reached only guarded scene execution.
- **the five scene critics** — continuity, causality, character intent, style, factuality — also reached only guarded scene execution.

And guarded scene execution required an executable chapter contract. When `contracts/chapters/` was empty, an agent listed it, found nothing, and dropped to a plain `draft-chapter` event. That single fallback disabled all three subsystems at once. It is what happened in every real session that motivated this release.

This release is not primarily new detection. It is wiring, plus the checks that wiring made possible.

## Changed

- **A chapter-queue event compiles a contract skeleton for every ready packet.** The directory is never empty, so an empty listing is never a reason to skip the guarded path. The skeleton carries only what the packet determines. The four fields requiring judgement — `start_state_ids`, `required_end_state`, `forbidden_changes`, `knowledge_boundary_ids` — are left empty and named in `missing_small_model_fields`. Inventing them would make guarded execution appear available while running against a hollow contract, which is worse than an honest failure. An authored contract, on disk or submitted with the event, is never overwritten. The event reports which contracts still need completion.

- **Style rules are measured against absolute reference bands.** Every style-pattern rule was relative: it compared a scope either to an accepted author baseline or to the rest of the corpus. Both go quiet on a manuscript that is uniformly AI-flavored, because nothing stands out against anything else — and `defaultVoiceGuardrails()` ships with a null baseline, so the stronger branch was silently disabled on any project that never accepted one. A shipped table of published-fiction bands now gives the rules a fixed reference. This also makes single-chapter linting possible at all: the corpus-concentration fallback needs several documents to mean anything.

- **A book plan whose chapters all carry the same `target_words` is rejected.** This corrects a tension introduced in v1.10.0. That release held a draft to 85%–110% of its packet target, which is right — but if every packet carries the same target, the band enforces uniform chapter lengths. Variance has to live in the plan, so it is checked where the plan is approved.

- **A `package` event requires that at least one human has responded to a reader experiment.** `RELEASE.md` has always said automated diagnostics are not human reader evidence, and the reader-kit subsystem existed to collect the real thing — but using it was entirely optional. A book could be planned, drafted, reviewed and packaged without one person reading a page. The rejection carries `human-gate-required` and is not retryable. The bar is that evidence exists, not that it is favourable: a `rejected` verdict is still real evidence, and whether to publish anyway is the writer's decision.

## Added

- **Deterministic prose lint on every `draft-chapter` event.** The same rules that previously waited for act review now run against the submitted chapter, before it applies, reported through the v1.10.0 advisory channel. The first style signal used to arrive five to eight chapters late, when the voice had set and revision was expensive. Lint reads the submitted text, not the copy on disk, so it measures what is actually being applied.

- **Per-character dialogue differentiation.** Everything else in the project that says "voice" means the narrator. Nothing asked whether two characters sound like different people. Dialogue is now attributed to named speakers and each speaker measured independently on sentence length, contraction rate, question rate, word length and vocabulary range; adequately-sampled pairs that cannot be told apart are reported. A finding is never produced from one shared trait — every measure must agree.

- **Structural rhythm advisories** for low chapter-length variance, perfectly periodic POV rotation, one causal joint covering most chapters, and repeated chapter-ending beats. Book-plan warnings previously had no delivery path at all and were discarded; they now reach the writer.

- **Repetition constraints in the drafting prompt.** The patterns the manuscript has already formed are carried into the draft prompt, so the drafter knows what it is about to repeat.

- **An explicit report when no voice baseline is accepted.** Silence and "the strongest rules were disabled" were previously indistinguishable. A `draft-chapter` event now says which checks actually ran.

## Compatibility and boundaries

Three classes of event that previously applied are now rejected: a book plan with entirely uniform chapter targets, a `package` event with no human reader evidence, and — from v1.10.0 — the existing draft-length and working-tree cases. The first two are new in this release, which is why it is a major version.

Every style finding is review evidence, not authorship detection. The tool never claims a passage was machine-written, and a deliberate voice choice can legitimately sit outside a band. The reference-band numbers are calibration defaults chosen to sit clear of ordinary stylistic range rather than at its edge; they are a starting point for review, not a quota to optimise against.

No project schema, workflow state, or evidence content changed. Existing projects remain readable, and contract skeletons are additive.
