# Novel Forge v1.7.4 — Registered Source Provenance Guidance

v1.7.4 is a guidance-only patch. It changes no project schema, workflow state, or evidence content.

## Fixed

- `SKILL.md` now states explicitly that every `source_ids` entry on a historical chronology, constraint, or knowledge-boundary item must be the `id` of a source actually registered in `research/source-register.yaml` — never a raw file path or the name of an existing in-project document such as `series/series-bible.md` or `series/canon.yaml`. When a fact genuinely comes from that kind of document, the guidance now states the concrete fix: register a source entry (with a stable `id`, e.g. `SRC-014`, and a `location` naming the document), submit `research/source-register.yaml` alongside `historical-context.yaml` in the same `book-plan` event, and reference the registered `id` instead of the path.

This fixes a real failure mode: a `book-plan` submission cited a document path (`series/series-bible.md`) directly as a `source_ids` value across multiple `HIST-NNN` and `HC-NNN` entries instead of registering it as a source. `historicalIntegrityFindings` correctly rejected the event with `HIST-NNN references missing source series/series-bible.md` and `historical-integrity` blockers, and the workflow stopped without retrying rather than bypassing the boundary — but the whole plan was discarded. The validator behavior was correct; the skill guidance did not previously say what a valid `source_ids` value must resolve to.

## Upgrade

Install from the pinned `v1.7.4` tag. This patch changes no project schema, workflow state, or evidence content, so existing projects remain fully compatible.
