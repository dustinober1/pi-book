# Novel Forge v1.9.1 — Drafting Boundary and Path Diagnostics

v1.9.1 closes the gaps that let a drafting session work around the transaction boundary instead of through it. It changes no project schema, workflow state, or evidence content.

## Fixed

- **The manuscript path rejection now states the naming rule.** A `draft-chapter` file must live in `books/<book-id>/manuscript/chapters/` with a file name that *begins with the chapter number* — `001-the-midnight-hatch.md`, not `chapter-001.md`. The rejection previously said only "is not allowed for draft-chapter", so the rule was invisible. It now names the required directory, the leading-number rule, and a valid example, and `SKILL.md` documents it.
- **`SKILL.md` forbids touching the project root outside an event.** The transaction rule named only `PROJECT.yaml`, `BOOK.yaml`, `STATUS.md`, and `HANDOFF.md`, which read as permission to write anything else. It now states that no file inside the project root may be created, moved, renamed, or deleted by any other means — file-write tool, `mv`, `cp`, `rm`, `mkdir`, shell redirect, or editor — that in-progress prose stays outside the project root, and that a rejection never licenses rearranging the working tree until a check passes.
- **`SKILL.md` no longer sends agents into the implementation source.** It previously told them to consult `src/domain/schemas.ts`, which invites reading a checkout that may be a different version than the one installed. It now directs them to the installed skill, the project's own files, and `novel_validate_event`, which reports the contract as actually enforced.
- **A missing chapter contract explains itself.** `novel_advance_chapter_step` failed with only "Chapter execution preparation requires books/<book-id>/contracts/chapters/CH-NNN.yaml". Both that failure and the not-small-model-ready failure now state that the contract is authored rather than generated, which fields it needs, that its path is allowlisted for `chapter-queue` events, and that a `draft-chapter` event is the interim path — while requiring the agent to say plainly that the chapter was drafted without guarded scene execution.
- **`novel_advance_chapter_step` enumerates its critics.** The `critics` parameter accepted any string, so a genre profile could be sent and rejected only afterwards ("Unknown scene critic: historical-fiction"). It is now a union of `continuity`, `causality`, `character-intent`, `style`, `factuality`, and `all`.
- `SKILL.md`'s structured-rejection section now lists `payload-validation` among the retryable codes, matching the v1.9.0 runtime, and states that an `allowlist-violation` means the submitted path is wrong.

These come from a real drafting session in which a misnamed chapter file produced two unexplained rejections; the agent then wrote 42 KB of prose directly into the project tree, moved it, ran `rm -rf` on the manuscript directory, and reverse-engineered the naming rule from an unrelated local checkout of this repository before finally applying the event.

## Compatibility and boundaries

Validation strictness is unchanged: the same paths and events are accepted and rejected as before, with better diagnosis. The `critics` parameter now rejects invalid values at the schema boundary rather than inside the handler; every previously valid value remains valid. Existing projects remain fully compatible.
